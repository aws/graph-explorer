Deploy Graph Explorer locally using the official Docker image from Amazon's ECR Public Registry.

You can find the latest version of the image on [Amazon's ECR Public Registry](https://gallery.ecr.aws/neptune/graph-explorer).

This guide is an example, not a recommended production configuration. Review its network, access control, and IAM choices against your own security requirements before you run it in production. For the hosting setups Graph Explorer supports, see [Supported Hosting](../../references/security/#supported-hosting). For general guidance on securing a production workload, see the [Security Pillar of the AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/security-pillar/welcome.html).

> [!NOTE]
>
> The `sagemaker-*` image tags are now aliases for the same image as the regular tag. They exist only for compatibility with existing SageMaker lifecycle scripts and will stop being published in a future release. Use the regular tag for new deployments.
>
> Because of this, a `sagemaker-*` tag starts with the standard defaults: HTTPS on port 443, which needs `HOST` set to generate its certificate. To serve HTTP on port 9250 with logs formatted for CloudWatch instead, set these variables:
>
> - [`PROXY_SERVER_HTTPS_CONNECTION=false`](../../references/configuration/#proxy_server_https_connection)
> - [`PROXY_SERVER_PORT=9250`](../../references/configuration/#proxy_server_port)
> - [`LOG_STYLE=cloudwatch`](../../references/configuration/#log_style)
>
> Publish the port with `-p 127.0.0.1:9250:9250` and open `http://localhost:9250/explorer`. Sending the logs to CloudWatch also takes Docker's `awslogs` log driver.

> [!IMPORTANT]
>
> The Graph Explorer server, not your browser, connects to the database for proxied connections, so it needs network access to the database endpoint. See [System overview](../../references/architecture/#system-overview) for details.

> [!IMPORTANT]
>
> Graph Explorer performs no authentication or authorization, so controlling who can reach a deployment is the deployer's responsibility. Never expose it publicly without an access control layer in front of it. See [Access Control](../../references/security/#access-control).

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) installed on your machine
- [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) installed on your machine

## Steps

1. Authenticate with the [Amazon ECR Public Registry](https://docs.aws.amazon.com/AmazonECR/latest/public/public-registries.html#public-registry-auth)

   ```bash
   aws ecr-public get-login-password --region us-east-1 | docker login --username AWS --password-stdin public.ecr.aws
   ```

2. Pull down the docker image

   ```bash
   docker pull public.ecr.aws/neptune/graph-explorer
   ```

3. Create and run a docker container using the image

   ```bash
   docker run -p 127.0.0.1:443:443 \
    --restart unless-stopped \
    --env HOST=localhost \
    --name graph-explorer \
    public.ecr.aws/neptune/graph-explorer
   ```

   The `HOST` environment variable is used for SSL certificates generation since HTTPS is the default. If you are hosting this on a public domain, you should replace `HOST=localhost` with your domain name.

   > [!IMPORTANT]
   >
   > `-p 127.0.0.1:443:443` publishes the container on the loopback interface only, so only the host itself can reach it. To reach it from other machines, such as on a public domain, use `-p 443:443`, which publishes it on every network interface of the host, and limit who can reach port `443` with network rules you provide. Confirm your rules apply to the port you publish, because container platforms can publish ports in a way host firewalls don't filter.

4. Open a browser and type in the URL of the Graph Explorer server instance

   ```
   https://localhost/explorer
   ```

5. You will receive a warning as the SSL certificate used is self-signed. Since the application is set to use HTTPS by default and contains a self-signed certificate, you will need to add the Graph Explorer certificates to the trusted certificates directory and manually trust them. See the [HTTPS Connections](../troubleshooting/#https-connections) section.

   > [!NOTE]
   >
   > A new container generates a new certificate, so replacing the container undoes this trust step. To keep the certificate, see [Keeping the certificate across container replacements](../../references/security/#keeping-the-certificate-across-container-replacements).

6. After completing the trusted certification step and refreshing the browser, you should now see the Connections UI. See [Connections](../../features/connections/) for details on configuring your first connection.

## Upgrading from 3.3 or earlier

The server now reads its startup configuration itself, where earlier versions ran shell scripts that rewrote files in the configuration folder. A deployment that follows this guide needs no change, apart from what is listed here.

- The image starts the server with node, and `docker-entrypoint.sh`, `process-environment.sh`, and `setup-ssl.sh` are removed. If your container's command calls `./docker-entrypoint.sh`, as a Kubernetes `command:` may, remove it.
- The configuration folder is no longer written, so you can mount it read-only. The container no longer stops with "Graph Explorer can't start because it can't write .env".
- `config.json` is read as JSON. Comments and trailing commas still work. A key inside a comment no longer takes effect, and a key written with a space before its colon now does, so check your `config.json` for both. A file that is empty, holds only comments, or isn't valid JSON stops startup with an error that names the file, so add settings to it, fix it, or remove it.
- An environment variable now overrides the same setting in `config.json`, including the Default Connection settings and `NEPTUNE_NOTEBOOK`, and a setting `config.json` leaves out now comes from the environment. Earlier versions used `config.json` for every such setting when the file existed. Where an `-e` flag and `config.json` set the same setting to different values, the `-e` value now wins, so remove the flag to keep the `config.json` value. See [Precedence](../../references/configuration/#precedence).
- With `-e NEPTUNE_NOTEBOOK=true`, the Neptune Notebook preset now applies even when `config.json` exists, so the server serves HTTP on port 9250. When `PROXY_SERVER_HTTPS_CONNECTION` is also `true`, from `config.json` or an `-e` flag, startup stops and names the conflict. To keep TLS, remove `-e NEPTUNE_NOTEBOOK=true` or set that flag to `false`, because a `config.json` value doesn't override it. To run under the preset, remove the HTTPS setting. See [Precedence](../../references/configuration/#precedence).
- An empty `-e` value for a setting `config.json` can hold, such as `-e GRAPH_CONNECTION_URL=`, counts as unset. See [Precedence](../../references/configuration/#precedence).
- The lines that earlier versions appended to `.env` at every start are ignored, also after the blank lines between them were removed. The server logs how many it ignored and never rewrites the file, so you can delete them.
- A `PROXY_SERVER_HTTPS_CONNECTION` line in `.env` now takes effect. Earlier versions ignored it: they served HTTPS when `cert-info` already held the certificate files, and stopped otherwise. A `false` there now serves HTTP, so remove the line to keep HTTPS. When HTTPS is off, the server logs where it was turned off, such as `HTTPS is off, set by PROXY_SERVER_HTTPS_CONNECTION in /graph-explorer/packages/graph-explorer/.env`, in place of `SSL disabled. Skipping self-signed certificate generation.`
- The same value now decides both whether the server uses HTTPS and whether it generates the certificate, so `-e PROXY_SERVER_HTTPS_CONNECTION=TRUE` or a `config.json` value of `"True"` now generates one.
- A new container that mounts a configuration folder from an earlier container generates its own certificate when `HOST` is set, as [HTTPS Connections](../../references/security/#https-connections) describes.
- A run from source (`pnpm start`) now reads a `config.json` at the repository root, the same way the image does.
- A key set more than once in `config.json`, `.env`, or `.env.local` now stops startup with an error that names the file, the key, and its lines, so keep one line for each key and remove the others. In `.env` and `.env.local`, earlier versions used the last line, so keep that one to start as before. The lines earlier versions appended to `.env` don't count.
- An `IAM` value other than `true` or `false` in any letter case now uses `false` with a warning, and `True` or `TRUE` now reads as `true`. Earlier versions wrote the value as it was, which could make a default connection the browser couldn't read.
- `GRAPH_EXP_FETCH_REQUEST_TIMEOUT` and `GRAPH_EXP_NODE_EXPANSION_LIMIT`, from `-e` flags or `config.json`, now reach the default connection. A value that isn't a positive whole number is left out with a warning.
